## 👋 About Me

I'm **Ahmed Raza Qadri**, a software engineer interested in building useful products and improving how applications are built, shipped, and operated.

My main focus is **Cloud & DevOps engineering**—especially containerization, CI/CD automation, Infrastructure as Code, cloud infrastructure, deployment reliability, and observability. I also build Flutter mobile applications and full-stack applications, which gives me a developer's perspective on the systems that run software.

- ☁️ **Cloud & DevOps:** AWS, Azure, Docker, Kubernetes, Terraform, CI/CD and Linux.
- 🔁 **Automation:** GitHub Actions, GitLab CI/CD, build/test workflows and deployment automation.
- 📱 **Mobile:** Flutter, Dart, Firebase, REST API integration and offline-first app patterns.
- 🌐 **Web & APIs:** Next.js, React, Vue.js, Node.js, PHP/Laravel and REST APIs.
- 🧠 **AI & Python:** Python, machine learning fundamentals and AI-powered application experiments.
- 📚 **Always learning:** cloud architecture, DevSecOps, monitoring, system design and production troubleshooting.

### 🏗️ What I aim to include in DevOps project documentation

- **Architecture:** application flow, cloud resources, network boundaries and data flow.
- **Infrastructure as Code:** Terraform layout, variables, state considerations and environment setup.
- **CI/CD:** source control → validation/tests → image build → security scan → registry → deployment.
- **Security:** IAM least privilege, secret handling, network restrictions and container image scanning.
- **Operations:** health checks, logs, monitoring, troubleshooting, rollback and recovery considerations.
- **Reproducibility:** prerequisites, commands, configuration examples, validation steps and cleanup instructions.
- **Evidence:** architecture diagrams, pipeline screenshots, test results and dashboards where implemented.

I'll distinguish **implemented and tested** features from **planned improvements** so readers can understand each project's actual state.
